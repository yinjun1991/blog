# 03｜循环规则建模与实例生成（RRULE/RDATE/EXDATE）

- 目标：以最小可用集合支持循环事件/任务，解释 RRULE/RDATE/EXDATE 的存储与在查询窗口内的展开策略。
- 范围：仅覆盖常见规则（每日/每周/每月/工作日），复杂 BYxxx 规则点到为止。

## 核心模型
- BaseItem：基础事件/任务（无展开），携带 `DTSTART` 与 `timezone`。
- Recurrence：`rrule`, `rdate[]`, `exdate[]`；与 BaseItem 关联。
- Exception：实例级覆盖（更新/删除将于后续两篇详述）。

## 生成策略（按窗口展开）
- 输入：`[windowStart, windowEnd]`；输出：该窗口内的实例列表。
- 算法要点：
  - 避免无限展开：依据 `COUNT/UNTIL` 限制或对窗口边界裁剪。
  - 先应用 `rdate`（补充），再过滤 `exdate`（剔除）。
  - 时区一致：以 `DTSTART` 所在时区计算，再转换为 UTC。
- 性能：
  - 对常见规则做迭代生成；按天/周步进，避免逐秒。
  - 对极长周期，可缓存最近查询窗口的实例。

## 存储建议
- 规则存文本（RFC 5545 格式）或结构化字段；文本更灵活，结构化更易查询。
- `exdate` 只存日期/时间戳；配合 Exception 表处理“单次改动”。

## 测试与验收
- 基本用例：每日/每周规则在两周窗口的实例数。
- 边界：DST 切换日、月底溢出（例如每月 31 号）。
- 规则终止：`COUNT` 或 `UNTIL` 生效校验。

## 规范速记（只提关键）
- RFC 5545：`RRULE/RDATE/EXDATE` 定义；`BYDAY/BYMONTH/BYSETPOS` 常用子句。
- 不展开 WebDAV/CALDAV，此处只关心本地生成策略。

## 小结
- 循环 = 基础项 + 规则 + 例外；查询时按窗口展开。
